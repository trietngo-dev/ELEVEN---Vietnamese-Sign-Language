# VSL Platform - Frontend Project Instructions

## 1) Mục tiêu dự án

Xây dựng ứng dụng web/mobile-first hỗ trợ:

- Học ngôn ngữ ký hiệu tiếng Việt theo lộ trình bài học.
- Phiên dịch ngôn ngữ ký hiệu theo thời gian thực (real-time).
- Chấm/kiểm tra động tác sau mỗi bài học.

Đây là đồ án team 3 thành viên, frontend được xây bằng React + Vite + TypeScript.

## 2) Bối cảnh sản phẩm

- Domain: EdTech + AI cho Vietnamese Sign Language (VSL).
- Dataset tham chiếu: VSL - Vietnamese Sign Language (UIT) trên Kaggle (4,362 video, 20.78 GB).
- Chiến lược dữ liệu: chọn lọc subset phù hợp để giảm dung lượng và tối ưu train/infer.

## 3) Vai trò của frontend (client)

Frontend chịu trách nhiệm:

- Trải nghiệm học (course list, lesson detail, progress tracking).
- Đăng nhập/đăng ký và quản lý hồ sơ người dùng.
- Hiển thị/kiểm soát trạng thái gói tài khoản (free/premium).
- Gọi API để:
  - Kiểm tra động tác theo bài học.
  - Phiên dịch real-time (khi đủ quyền gói).
  - TTS phản hồi kết quả học/phiên dịch.
- Hiển thị giới hạn số lần dùng tính năng theo tháng theo từng gói.

## 4) Công nghệ frontend chính

- Framework: React 18 + Vite + TypeScript.
- UI/UX: Tailwind CSS + shadcn/ui + Framer Motion.
- Data fetching/cache: TanStack Query (React Query).
- Global state: Zustand.
- Form + validation: React Hook Form + Zod.

## 5) Tích hợp AI và xử lý tín hiệu (định hướng hệ thống)

Lưu ý: phần model/ML nặng chạy ở backend/service, frontend chỉ capture stream và hiển thị kết quả.

Các thành phần AI dự kiến:

- MediaPipe Holistic: nhận diện keypoints/cử chỉ từ camera stream.
- Gemini models:
  - gemini-2.5-flash
  - gemini-2.5-flash-lite
  - gemini-3-flash (free tier)
- TTS:
  - Ưu tiên Gemini TTS (nếu ổn định và phù hợp chi phí).
  - Fallback Google TTS khi cần.

Frontend cần thiết kế UI linh hoạt để thay đổi provider/model mà không phải sửa nhiều view.

## 6) Chức năng bắt buộc (MVP)

1. Authentication

- Đăng ký, đăng nhập, đăng xuất.
- Lưu session/token an toàn ở client.

2. Khóa học và tiến trình

- Danh sách khóa học, bài học.
- Theo dõi tiến trình hiện tại theo user.
- Đánh dấu hoàn thành bài học.

3. Phân quyền theo gói tài khoản

- Free: quyền cơ bản, giới hạn số lượt kiểm tra/dịch theo tháng.
- Premium: tăng quota/thời lượng/tần suất dùng real-time translation và motion check.

4. Kiểm tra động tác & dịch real-time

- Camera permission + UI trạng thái nhận diện.
- Gọi API suy luận và hiển thị kết quả gần real-time.
- Đếm và hiển thị số lượt còn lại trong tháng.

5. Thanh toán/nâng cấp gói

- Luồng nâng cấp gói và cập nhật quyền sau thanh toán.
- Hiển thị rõ quyền lợi trước/sau nâng cấp.

## 7) Kiến trúc dữ liệu và dịch vụ liên quan

- Backend chạy VPS DigitalOcean 24/7.
- FE deploy miễn phí (Vercel/Netlify tùy team quyết định).
- Domain mua tại TenTen, trỏ DNS về backend VPS.
- Supabase PostgreSQL: quản lý users, courses, progress, subscription, usage logs.
- Cloudinary: lưu video bài học và media assets.
- Mobile app có thể gọi cùng API backend qua HTTP/HTTPS.

## 8) Định hướng module frontend

Đề xuất module theo feature:

- auth/
- courses/
- lessons/
- translation/
- motion-check/
- subscription/
- billing/
- profile/
- shared/

Mỗi module nên gồm:

- components/
- pages/
- api/
- hooks/
- schemas/ (Zod)
- store/ (Zustand, nếu cần)

## 9) Nguyên tắc UI/UX

- Mobile-first, responsive tốt trên desktop/mobile.
- Feedback rõ ràng cho các trạng thái:
  - loading
  - success
  - error
  - no-permission
  - quota-exceeded
- Luôn có fallback khi camera/API/TTS lỗi.
- Animation vừa đủ (Framer Motion), ưu tiên hiệu năng.

## 10) Quy ước chất lượng code

- TypeScript strict, tránh any.
- Tách rõ layer UI <-> API <-> state.
- Chuẩn hóa type response từ backend.
- Dùng React Query cho async state/server cache.
- Dùng Zod để validate dữ liệu form trước khi gọi API.
- Viết component tái sử dụng, ưu tiên composition.

## 11) Rủi ro và lưu ý kỹ thuật

- Real-time inference phụ thuộc độ trễ mạng và tài nguyên server.
- Camera permission khác nhau giữa trình duyệt/thiết bị.
- Chi phí AI/TTS có thể tăng nhanh theo số người dùng.
- Cần theo dõi quota để tránh vượt chi phí gói.

## 12) KPI gợi ý cho demo đồ án

- Tỷ lệ hoàn thành bài học.
- Số phiên luyện tập/tuần.
- Độ trễ phản hồi kiểm tra động tác.
- Tỷ lệ thành công của phiên dịch real-time.
- Tỷ lệ chuyển đổi nâng cấp gói.

## 13) Scope ưu tiên theo phase

Phase 1 (MVP):

- Auth + Courses + Progress + basic motion check.

Phase 2:

- Real-time translation + quota by subscription.

Phase 3:

- Billing nâng cao + analytics dashboard + tối ưu UX.

## 14) Ghi chú triển khai

- Frontend KHONG xử lý train model trực tiếp.
- Frontend tập trung vào trải nghiệm người học, quản lý trạng thái và điều phối API.
- Mọi endpoint cần có versioning (vd: /api/v1/...) để dễ nâng cấp hệ thống.
- Các text set cứng (không lấy từ API) phải được đặt trong locales/vi.ts
